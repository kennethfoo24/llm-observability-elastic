## I1 (Important): X-ray breakpoint defined in two places; citation chips do nothing below xl; sheet trap leaks after a resize
Facts: `App.tsx:44` uses `matchMedia("(max-width: 1279px)")` (px) while the layout uses Tailwind `xl` = 80rem (`AppShell.tsx`, `XRaySheet.tsx`); with a large default font the two disagree and the X-ray is unreachable; `onCitation={selectCitation}` never opens the sheet below xl; if the sheet is opened below xl and the viewport grows past xl the sheet is `display:none` but its Tab trap and body scroll lock stay active.
FIX: add ONE hook `frontend/src/hooks/useMediaQuery.ts` (`useMediaQuery(query: string): boolean`, uses `matchMedia` with `addEventListener("change")`, guarded when `matchMedia` is missing (returns false), updates on change) and use `const xrayInline = useMediaQuery("(min-width: 80rem)")` in App as the SINGLE source of truth: the Inspect click AND the citation click open the sheet when `!xrayInline` (select + highlight + open), do nothing extra when inline; an effect closes the sheet (calls the same close handler so focus/scroll lock are released) when `xrayInline` becomes true. Remove the px query. Tests: citation click below xl opens the sheet and highlights the doc; Inspect opens it; when the media query flips to wide the sheet closes and `document.body.style.overflow` is restored; hook unit test with a mocked matchMedia including the change event and the missing-matchMedia case.

## I2 (Important): guardrail panel says "Clean / 0.00" when the injection model never answered
Facts: on a cold or failed injection model the backend (`backend/app/guardrail.py`, `backend/app/chat_service.py` fallback) returns verdict CLEAN with `injection_score 0.0` and `status "degraded"`, and the UI renders a teal "Clean" with "Injection probability 0.00". A prompt-injection red-team prompt could pass unblocked while labelled Clean.
FIX (backend + UI, one coherent change): 
- Backend: `Verdict.injection_score` becomes `float | None`; `Guardrail.check` sets it to `None` when the injection model result was not obtained (timeout, error, malformed), and the chat_service fallback (guardrail.check raised) also uses `None`; the `/api/chat` response field `guardrail.injection_score` is then `null` in those cases (keep a float when the model answered). `aggregate_verdict` signature unchanged; no other behaviour change (regex PII still flags; fail-open stays). Update backend tests (guardrail tests assert None on timeout/model-down/malformed and a float when it answered; chat_service test for the raising-guardrail fallback; the stub keeps floats). The painless pipeline is unrelated; leave it.
- UI: `Guardrail.injection_score: number | null` in types; `GuardrailStrip` shows "Injection probability: n/a" when null and, when the verdict is not FLAGGED and the injection score is null, the verdict word becomes "Patterns only" (new neutral state: neutral icon, `on-ink-muted` tone, NOT teal) with the existing "Degraded" badge and one explanatory line "The injection model did not answer, so only pattern checks ran."; FLAGGED stays "Flagged" (or "Blocked" per Minor 2). Update AssistantMessage's DegradedNote copy if needed to stay consistent. Tests for each state.
